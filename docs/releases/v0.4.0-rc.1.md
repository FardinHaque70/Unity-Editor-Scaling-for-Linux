# v0.4.0-rc.1 — AppImage release candidate

**Publication status: pending artifact and Unity acceptance.** This document describes the candidate; it does not certify a release or completed test matrix.

Unity Editor Scaling for Linux now packages its GTK settings app and native backend as one x86_64 AppImage. Each Editor keeps its Custom scale toggle and 100–200% scale setting. Changes take effect after restarting Unity.

## Changes

- Bundled Python, PyGObject, GTK 4 and libadwaita; no compiler or Python package installation on the user's computer.
- Prebuilt, relocatable native components with `product-profile-v2` and schema-2 activation records. Existing native scale, geometry, input and allocation/repaint calculations are retained.
- Standard XDG preferences independent of the application image, with migration of schema-2 settings from the previous source installation.
- One managed AppImage, the existing application-menu identity and the `unity-scale` command.
- User-requested update checks, release notes, progress and cancellation. A pinned Ed25519 key and signed manifest authenticate updates; atomic replacement includes health verification and rollback.
- Native components remain beside each Editor and continue working after the GUI closes. No startup service, background update checks or telemetry.

## Compatibility

Initial support is limited to the exact Unity **6000.3.27f2 Linux x86_64** executable on **KDE Plasma Wayland**, with Unity using its existing X11/Xwayland GTK 3 path and **OpenGL**. Editor files must be owned and writable by the current user. Editor paths containing spaces or colons, root-owned installations, other Unity builds, Vulkan and live scaling are unsupported. The AppImage itself supports paths containing spaces.

The AppImage is built against Ubuntu 22.04. Its statically linked Type-2 runtime does not require the host `libfuse2` package; `--appimage-extract-and-run` supports hosts where mounting is unavailable. The host still supplies its graphics drivers, base runtime and Unity's normal runtime requirements.

## Acceptance and limits

Earlier native development builds have bounded physical click/menu and floating Scene/Game/Inspector observations on the target KDE/NVIDIA system. Those records do not establish acceptance of this newly packaged artifact. The release candidate must pass its artifact, migration, update and private Unity checks before publication; the final release record should name the tested artifact SHA-256 and measured results.

Performance equivalence across projects, every Editor workflow, mixed-DPI transitions and all percentages has not been established. Report repeatable rendering, input, menu, resizing or docking problems with the distribution, desktop/session, GPU driver, Unity build, selected scale and reproduction steps. A saved percentage or a successful automated test alone does not prove correct Unity rendering.

## Installation and recovery

Download `Unity-Editor-Scaling-for-Linux-x86_64.AppImage`, make it executable, and open it after saving work and closing Unity. Existing Custom scale choices are migrated. Scale settings remain shared across projects using the same Editor.

Custom scale off selects Unity default after restart and retains the native connection. Restore each Editor with `unity-scale restore --editor /absolute/path/to/Editor/Unity` before updating/removing that Editor or uninstalling this app. Preserve the original backup until restoration succeeds. See [installation and recovery](../INSTALL.md).

Release assets are the AppImage, `SHA256SUMS`, signed `release.json` and `release.json.sig`, release notes and source. Unity Editor and Unity Hub are not redistributed.
